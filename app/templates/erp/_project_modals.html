Why they moved. Each of these used to sit at the foot of the list it belonged to, inside an `aurora-disclosure`: three to six fields tall when open, and still a row of trigger buttons when closed. Across the four tabs that was sixteen of them. They were most of the reason a tab could not fit one viewport, and on Logistics they pushed the tasks the reader came for below the fold. A dialog costs nothing when it is closed and covers the record only while it is open. It is a `:target` dialog -- the trigger is an ordinary link to the dialog's id and the close control is a link back to `#` -- so it needs no JavaScript and no inline handler. The contract test forbids the second; the no-JS contract forbids depending on the first. Nothing about any form below changed: same action, same method, same field names, same CSRF and version inputs, same server validation. The one addition is `next`, which `_redirect_to_tab` already honours, so saving returns to the section and page the reader was on.
